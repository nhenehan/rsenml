# rsenml compared with other Rust SenML crates

Generated by `compare/` (`cargo run --release`); every number and verdict below comes from that run. Do not edit by hand: rerun it.

## Method

- **Libraries run**: rsenml (this repository), sindit-senml 0.3, senml-cbor 0.1, coapum-senml 0.1 (default features: JSON and CBOR), all from crates.io via `compare/Cargo.lock`. Not run, by licence: senml-deser (OLFL-1.3) and erxi (PolyForm Noncommercial); their source review is in `doc/landscape.md`.
- **Calls**: rsenml `json::decode`, `cbor::decode`, `cbor::decode_sensml` (validate on decode); sindit-senml `parse_json` (decode, validate, resolve: its only public reader); coapum-senml `SenMLPack::from_json_bytes` then its own `validate()`, and `from_cbor_validated`; senml-cbor `cbor::decode` into a 256-record array. Every call is wrapped in `std::panic::catch_unwind`.
- **Oracle**: expected records are written as JSON text and read with serde_json, independently of every library under test; RFC examples are their own oracle (the RFC text). Resolution uses an independent resolver written from sections 4.5-4.6 (`compare/src/model.rs`); as a check, it resolves the 5.1.3 example to exactly the 5.1.4 resolved example: **yes**. "Now" for relative times is 1700000000 for every library.
- **Data checks**: for an accepted vector, libraries that expose records as written (rsenml, coapum-senml, senml-cbor) are compared field by field and exactly against the expected records (all 15 labels; a label the library cannot represent counts as missing data). sindit-senml exposes only resolved records, so it is compared against the oracle's resolution, in time order, numbers within 1e-6 + 4 ulp. rsenml is additionally checked the same way through its own `Pack::resolve`. Extension labels are not compared.
- **Expectations**: each vector cites its RFC 8428 section. Basis *normative* means a MUST, a table or the section 11 CDDL decides it; *reading* means the RFC is indirect and the expectation is this harness's reading (stated in the description). Vectors: 38 JSON, 26 CBOR (incl. 1 SenSML).
- **Machine**: x86_64 / AMD Ryzen 7 7840U w/ Radeon 780M Graphics; rustc 1.99.0 (b940084d7 2026-09-28); cargo 1.99.0 (5f94df478 2026-08-27). Timings: median of 51 samples, each a batch of calls lasting at least 200 µs, after warm-up; release profile with `lto = true`, `codegen-units = 1`. One run on a desktop machine: treat differences under ~20% as noise.

## 3. Encoded sizes

Each library encodes the data from its own reading of the JSON. *Faithful* means its own decoder reads the output back to the expected resolved records; a size that is not faithful is for less data. The synthetic pack is 200 records in resolved form (no base fields, absolute times), so every library can carry it. Minimal `#![no_std]` `#![no_main]` binaries under `compare/footprint/`, built with `--profile footprint` (`opt-level = "z"`, `lto = true`, `codegen-units = 1`, `panic = "abort"`) and linked by rust-lld with `_start` as the only root. Each decodes one pack and re-encodes it, with a spinning panic handler. The alloc-needing ones use the 32 KiB bump allocator of `footprint/common/bump.rs` (which shows in `.bss`). Sizes from the ELF section headers, in bytes.

| binary | `.text` | `.rodata` | `.data` | `.bss` | `.text` above baseline | what it does |
|---|---|---|---|---|---|---|
| baseline | 808 | 8 | 0 | 32772 | 0 | runtime + bump allocator, one allocation, no codec |
| rsenml `cbor` | 29152 | 3832 | 0 | 32772 | 28344 | decode + validate + encode the RFC section 6 dump; bump allocator |
| rsenml `json` | 39828 | 5792 | 0 | 32772 | 39020 | decode + validate + encode the 2nd example of 5.1.2; bump allocator |
| rsenml `exi` | 96572 | 30464 | 0 | 32772 | 95764 | decode + validate + encode the RFC section 8 bit-packed dump; bump allocator |
| senml-cbor | 5668 | 539 | 0 | 0 | 4860 | decode + encode the RFC section 6 dump; no allocator (fixed arrays) |

sindit-senml and coapum-senml need `std` and are not measured here. The four binaries do not process the same pack in every case (EXI uses the section 8 dump of the first 5.1.2 example; the others the second 5.1.2 example), which does not change which code is linked.

## Not measured

- Heap allocations per call, and peak memory: not instrumented.
- Robustness beyond these vectors (fuzzing).
- Footprint of sindit-senml and coapum-senml (`std` only), and of rsenml `xml`.
